# Compare Page Rebuild — Production Report

**Date:** 2026-08-01
**Scope:** Full rebuild of `/compare` into a premium, Apple/Tesla/Rivian-inspired EV comparison experience, while staying built from EV Motion's existing design language (not a redesign).

---

## 1. Features implemented

- **Compare Hero** — heading, subtitle, category tabs (only while no vehicle is selected), 2-3 vehicle slot cards with VS badges, Change/Remove controls, a live Winner Ribbon.
- **Change Vehicle modal** — premium searchable Command-palette modal (Dialog + cmdk), category-locked, excludes already-selected vehicles, Recent + Popular groups, full keyboard navigation.
- **Sticky comparison nav** — 17-section scroll-spy nav (Overview, Price, Battery, Charging, Performance, Ownership, Running Cost, Dimensions, Safety, Features, Warranty, Colours, Pros & Cons, Expert Verdict, Reviews, News, FAQs), sticky below the main Navbar, smooth-scrolls to each section.
- **Winner engine** — a generic, real-data-only scoring engine. Crowns a winner per metric only when ≥2 compared vehicles have real data for it (never an automatic "win" from a single known value against unresearched blanks). Powers the Winner Ribbon, per-cell crown badges, RatingsSection, and SmartRecommendation.
- **Overview** — premium stat-card grid (Battery, Range, Power, Torque, Top Speed, Acceleration, Charging Time, Efficiency), each card showing every compared vehicle's value with the winner crowned.
- **Price Comparison** — city-aware on-road price breakdown (Ex-showroom, RTO/registration, Insurance, FASTag, Logistics & Handling, Total), a "Change City" control that live-recomputes RTO/Insurance/Total (verified: Kohima → Delhi changed all three vehicles' totals), plus a working **EMI Calculator** (down payment / interest rate / tenure sliders → EMI / total interest / total cost, instant recompute).
- **Battery** / **Charging** — capacity, chemistry, range, DC/AC charging times, connector type, V2L/V2V, charging network partner.
- **Performance** — power, torque, acceleration, top speed, drive modes, regen braking, motor type, drive layout.
- **Ownership Cost** — annual charging cost, insurance, road tax, a computed 5-year cost total; maintenance/service/battery-replacement/resale honestly show "Not officially specified" (no source data exists for these anywhere in the project).
- **Running Cost** — working **Charging Cost Calculator** (electricity rate / monthly distance / efficiency / home-charging % → monthly/yearly cost, savings vs petrol, savings vs diesel), all assumptions labeled.
- **Dimensions, Safety, Features, Warranty** — real spec tables with winner crowns where the underlying metric is scoreable; "Not officially specified" for any absent field (which is most vehicles outside the 15-vehicle pilot batch — see §7).
- **Colours** — clickable swatches per vehicle (no manufacturer imagery, matching the site's existing photo policy).
- **Pros & Cons** — Pros are each vehicle's real curated `highlights`; Cons are computed, factual losses from the winner engine ("Lower range than the Nexon EV"), never an invented qualitative claim.
- **Expert Verdict** — templated, neutral "who should buy this" copy generated from real winner-tally + price-tier data, not editorial opinion.
- **Ratings** — 0-10 scores computed *relative to the vehicles being compared* (Overall, Performance, Charging, Safety, Value, Ownership); Comfort and Technology always show "Not enough data" since no feature-checklist/comfort data exists anywhere in the schema.
- **Reviews** — real, per-vehicle local review state with a working submission form (honest empty state until a review is submitted, same pattern as the VDP).
- **News** — honest empty state (no real news data source exists anywhere in the project).
- **FAQs** — auto-generated comparison FAQs from real data ("Which has a longer range?") plus each vehicle's own real FAQs.
- **Similar Comparisons** — horizontal carousel of ≥8 smaller comparison cards, generated from `getRelatedVehicles()`, excluding vehicles already in the current comparison.
- **Smart Recommendation** — "Which one should you buy?" tags (Best Value, Best Range, Best Performance, Best Family EV, Best City EV, Best Highway EV, Best Premium EV), each only assigned when the underlying data genuinely exists.
- **Floating Summary Panel** (desktop only) — current winner, categories won, price difference, running-cost difference, jump-to-section, Change City, Share (Web Share API with clipboard fallback), Download PDF.
- **PDF export** — one-click, real PDF file (not a browser print, not a DOM screenshot) with EV Motion branding, vehicle names, date, city, and every comparison section as vector tables, footer "Generated by EVMotion.in".
- **Ad placements** — leaderboard below navbar (both `/compare` and `/compare/[slug]`), rectangle slots after Battery and Ownership, leaderboards before Similar Comparisons and above the footer, matching the VDP's existing placement convention.

## 3. Routing changes

- **`/compare/[slug]`** (new) — canonical comparison URL, e.g. `/compare/tata-nexon-ev-vs-mg-windsor-ev`. Deliberately has **no `generateStaticParams`** — unlike every sibling `[slug]` route, the combinatorial space (C(54,2)+C(54,3) for cars alone) is too large to pre-render; renders on demand.
- **`/compare`** (rewritten) — picker/landing page. Resolves the legacy `?ids=slug1,slug2` query param; redirects to the canonical URL when 2-3 valid same-category vehicles resolve, otherwise renders the empty-slots hero.
- Every existing site-wide entry point (homepage `CompareCard`, every `VehicleCard`'s "Add to Compare", VDP `VehicleHero`, VDP `SectionCompareSimilar`, footer link) still works unchanged or was upgraded to link directly to the canonical URL (`CompareCard`, `SectionCompareSimilar`).
- `sitemap.ts` gained entries for the curated homepage comparison pairs.

### Bugs found and fixed during QA

1. **Winner engine false-positive.** A metric known for only 1 of 3 compared vehicles (the rest unresearched/`null`) was auto-crowned a "winner" — nothing to actually beat. Fixed: `computeWinners()` now requires ≥2 known values to declare a winner; otherwise "insufficient data."
2. **`ChangeVehicleModal` runtime crash.** This repo's local `CommandDialog` only provides the Dialog shell — it does not wrap children in cmdk's `<Command>` store provider (unlike the upstream shadcn convention). Omitting that wrapper crashed with `TypeError: Cannot read properties of undefined (reading 'subscribe')` the moment "Change Vehicle" was clicked. Found via live browser testing (not caught by `tsc`/`eslint`/`build`), fixed by wrapping in `<Command>` explicitly. Documented in `CLAUDE.md` point 14 so it isn't reintroduced.

## 6. Accessibility verification

- Semantic `<table>` markup for every spec comparison (matching the VDP's existing `SectionCompareSimilar`/`SectionVariants` convention), with `<caption className="sr-only">` and `scope="col"`/`scope="row"`.
- `.focus-ring` on every new interactive element, matching the sitewide convention.
- `aria-expanded`/`aria-controls` on accordions (via the reused `Disclosure` primitive) and the Reviews form toggle.
- `ChangeVehicleModal` inherits full Dialog + cmdk accessibility (focus trap, `role="dialog"`, keyboard navigation, `aria-label`s) once composed correctly (see bug #2 above).
- `CompareStickyNav` uses `aria-current="true"` on the active section link.
- Winner crown icons are `aria-hidden`, paired with a `sr-only "(winner)"` text alternative so screen readers announce the win without relying on icon color/shape alone.
- Category tabs use `role="tablist"`/`role="tab"`/`aria-selected`.
- Not independently audited with automated tooling (axe-core, screen reader) — same unchanged limitation as the rest of the site.

## 8. Data honesty — the central design constraint

The original spec asked for Safety/NCAP/ADAS, Dimensions, Warranty, Features, and subjective Ratings — none of which existed anywhere in the project's `Vehicle` schema. Per explicit direction: **never fabricate or hardcode values.** A new, parallel `Vehicle.specs` field (`src/types/vehicle.ts`) was added — fully optional at every level, real/sourced data only — and populated via web research for a **15-vehicle pilot batch** (9 cars, 6 two-wheelers — the vehicles this task's own spec referenced and/or already appear in the homepage's curated comparisons). Every other vehicle (107 of 122) has `specs` fully `undefined`, and every UI surface reading it renders **"Not officially specified"** rather than guessing.

Pros/Cons and Expert Verdict are similarly computed from real winner-engine results rather than authored copy. Ratings are explicitly labeled as *relative to the vehicles being compared*, not an absolute or editorial score, and Comfort/Technology are always "Not enough data" since no backing data exists for them anywhere.

Full batch details, sourcing methodology, and next-steps: see `HANDOFF.md`'s "Batch 6 — Extended Spec Research" entry in the Full-Market Expansion batch log.
